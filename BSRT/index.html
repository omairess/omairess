    Task

    Protocol

    BSRT defaults reproduce the standard OSLER protocol: a 1 s stimulus every 3 s, sleep onset at 7 consecutive misses (21 s), 40 min maximum. The PVT default is a 10 min run with 2/4/6/8/10 s intervals.

    Regular protocol: 500 ms is the conventional lapse threshold.

    A response within the hit window is a hit; a slow hit (beyond the lapse threshold) is a lapse. A response later than the hit window is a miss — its raw reaction time is still recorded, but it does not reset the consecutive-miss run. A response under the false-start threshold is a false start.

    Corrections

    Applied to the corrected columns only. Raw values are always exported untouched.

    False starts are removed first, so they cannot inflate the mean and SD that define the outlier bounds. Bounds are computed within each block, so per-minute corrections use that minute's own mean and SD.

    Device check

    Every trial measures the display and the input path automatically and records the result with the data. Run it here first if you want to know whether a machine is fit to test on before you start.

    This chooses which clock reading becomes the scored reaction time. Both are always measured and exported either way (rt_event_ms, rt_handler_ms, input_delay_ms), so the correction can be checked, reproduced or undone in analysis rather than taken on trust. The desktop build has the same setting and the same default, so the two stay comparable.

    Connection speed does not affect reaction times here. The whole task runs inside this browser: once the page has loaded, every stimulus is drawn by the local display and every keypress is timed by the local clock, so nothing crosses the network between the two. How the page was delivered is recorded as provenance only.
